How it works

One page per shot, rendered frame by frame

Every shot is a small HTML page with one SVG. window.renderFrame(t) draws the frame for time t. A headless browser steps through t = 0, 1/24, 2/24… and ffmpeg stitches the screenshots. Nothing depends on real time, so any frame renders the same way every time, and a model can preview the exact moments it needs to check.

  1. Step 1Set the lookPaste the style system prompt once, at the start of the session.
  2. Step 2Build the kitOne run builds the reusable instruments and two demo sheets. Review them before any scene work.
  3. Step 3Brief each shotGive the narration, the beat words with times, and a scene prompt. Ask for previews at every beat.
  4. Step 4FinishMap the music's beats, then composite: HUD, kick punch, cut flashes, bloom, grain.

The style system

prompt · style system
You are a motion designer and front-end engineer. Build each shot as one self-contained HTML page with a single 720×1280 SVG, rendered at 1.5× to 1080×1920, 24 fps.

LOOK: a precision scientific instrument measuring the subject. Glyph specimens with metric lines, live plots, ray diagrams, spectrograms, 3D wireframe grids, callout lines with small data readouts. Calm, exact, premium. Never cartoonish.

PALETTE (nothing else)
- background #0a0a0b with a faint measurement grid: cream at 5–6 %, 40 px cells, small + marks at intersections
- signal orange #ff5a1f: only the one thing that matters right now. Max two orange elements on screen. Flat colour, no gradients.
- cream #ede6da for all type and lines. Hierarchy by opacity only: 100 / 60 / 35 / 15 / 6 %.
- paper scenes only: cream paper #ede6da with fibre/noise texture, black ink #0a0a0b, red rubber stamp #d1242a, no orange

TYPE
- hero letters: Anek Devanagari, weight 800, width axis animated 75↔125, 180–460 px
- Latin display: Archivo, weight 800–900, width 125, uppercase, tracking −0.01em, 44–150 px
- HUD labels: JetBrains Mono 500, uppercase, tracking 0.12em, 11–16 px (values 18–40 px)
- quiet lines: Instrument Serif italic, sentence case, 36–84 px
- margin notes: Kalam, rotated −5°…+3°, with a hand-drawn arrow
Pair every hero glyph with a small mono gloss (HINDI · "SCAN"). On-screen text must match the script exactly.

GLYPH SPECIMEN (signature element)
A giant glyph with full-width hairlines for HEADLINE/SHIROREKHA, BASELINE and DESCENDER (Latin: CAP-HEIGHT, X-HEIGHT, BASELINE). Label each in tiny mono with a unit value, add a side ruler, a bracket callout on one stroke (STEM 118 U) and a live WDTH readout. Measure line positions from the rendered glyph after fonts load, never from guesses.

LINES
Hairline 1.25 px, rule 2 px, heavy 4 px, round caps. Crosshair nodes r 6–14. Callouts: dot → straight or orthogonal leader → mono label + value box.

MOTION
Draw-ons with outExpo. Snap-ons with a 2-frame flicker (0 → 1 → .35 → 1). Counters that tick in mono, scanning cursors. No bounce, elastic or overshoot. Land each visual exactly on its beat, the moment the narrator says the word, anticipating by at most 0.08 s. Keep something alive until the last frame: slow drift, a scanning cursor, a flickering last digit. Cuts are hard, so show the first element within 2 frames.

DETERMINISM
window.setup() builds the SVG. window.renderFrame(t) sets the entire frame for time t in seconds. No CSS animations, transitions, requestAnimationFrame or Math.random; use a seeded RNG. Any frame must render correctly in any order.

LEAVE TO COMPOSITING
Crop marks, timecode, BPM counter, beat LEDs, grain, vignette, bloom, chromatic aberration, flashes, glitches and camera shake. Keep y 0–80 and y 1190–1280 clear. Keep important text inside x 40–650, y 110–1060.

LOGOS
Never draw or imitate a real logo. Place supplied logo files on a small cream plate with a mono caption, or use plain type.

The component kit

Build the instruments once

Every scene reuses the same parts, so build them first and review two demo sheets before any shot. In our run the kit took one Codex session. Its own previews caught a label collision and a glyph running off the edge, and it fixed both before it stopped.

prompt · component kit
Using the style system above, build lib/inst.js: one global INST object, plain JavaScript, no dependencies. Every component is a pure function of its options that returns SVG markup, or an object { svg(), update(t, …) } that sets attributes for time t. Expose INST.C (colour tokens) and INST.a(alpha) for cream at any opacity.

1. page({paper, grid}): root SVG with shared defs (paper texture filter, stamp distress mask, chevron markers) and the measurement grid
2. drift(t, dur): slow scale/pan transform for a content group
3. deva / display / mono / serif / note(text, opts): the five type roles. note() adds a slightly wobbly hand-drawn arrow to a target point.
4. scramble(str, t, t0, t1, seed), flicker(t, t0), dash(el, length, progress)
5. specimen({str, script, size, wdth, metrics, ruler, stem}): the glyph specimen, with metric lines measured from the rendered glyph; update(t, {wdth, reveal})
6. ruler, callout (dot → leader → label + value, draws on), plot (axes, 6 % gridlines, live orange series, scan cursor with readout)
7. spectrogram (≤ 3000 cells, hottest cells orange), wire (grid | sphere | terrain | ring, perspective projection, rotating)
8. ray and fan (dashed construction rays with chevrons), node (crosshair + mono label), packet (small orange square + mono tag, short fading trail)
9. qr: a fictional QR-style matrix that builds in raster order behind a scan line. It must not encode real data.
10. counter (display or mono, Indian or Western digit grouping), phone (wireframe outline with mm dimension lines and a screen group that can flash to cream)
11. stamp (red rubber stamp: double-rule box, distressed ink, slams 1.25 → 1 in 3 frames), ledger (ruled ink table with handwritten cells), hex (scrambling hex bytes)

Also build kit_demo.html (dark) and kit_paper.html (paper) showing every component. Preview frames at 0.2, 1, 2 and 3 s. Look at them at full size and fix anything misaligned, clipped or cluttered before you stop. Keep a frame under 1 s to render.

prompt · compositor
Write a frame compositor in Python with OpenCV and numpy (1080×1920, 24 fps). It reads the shot list and the rendered shots and applies, in this order:

1. Camera, content only. Each kick adds a zoom punch of 1.7 % × strength decaying with τ = 85 ms. Each snare adds a micro-shake of 6 px × strength, oscillating at 17 Hz and decaying with τ = 70 ms, in a random direction per hit.
2. Cuts. On the first frame of every shot, a flash (blend 55 % toward #ede6da, then 18 % on the next frame) and a glitch for 3 frames: 7–12 horizontal bands shifted up to ±70 px plus a 9 px RGB split, decaying 1 → 0.55 → 0.25.
3. HUD, fixed on screen, JetBrains Mono, cream at 60–85 %: L-shaped corner crop marks (44 px legs, 2 px, 48 px from the edges). Top-left: project name, scene counter (SC 07/52) and scene name. Top-right: timecode HH:MM:SS:FF and "24 FPS 1080x1920". Bottom-left: "BPM 110.0  BAR 031  BEAT 2/4". Bottom-right: four beat LEDs that light orange on their beat and fade with τ 0.16 s, plus K and S LEDs that flash on kicks and snares.
4. Captions (presenter and B-roll shots only): a dark readout plate (#0a0a0b at 64 %, 1 px cream border at 22 %, corner ticks), Archivo wide caps, the word being spoken in #ff5a1f and upcoming words at 45 %, snapping on with a 2-frame flicker.
5. Finish. Orange-masked bloom plus a weak white bloom, radial chromatic aberration, vignette and monochrome grain, with the settings in the table.

Add a --frames option that writes a few stills so you can check a look without rendering the whole reel.
prompt · beat map
Analyse the music bed and write beats.json for the compositor: bpm, phase, beats, bars, kicks and snares, each hit with a strength from 0 to 1.

1. Tempo and phase. Compute onset strength in four bands (35–120 Hz, 120–1000 Hz, 1–4.5 kHz, 4.5–11 kHz). Grid-search BPM within ±0.1 in steps of 0.005, and the phase, so onsets land on the 8th-note grid. Do not trust a single autocorrelation estimate: a 0.1 % tempo error drifts about 90 ms over two minutes, which is enough to miss every hit in the last third.
2. Downbeat: the beat position (0–3) with the strongest low-band onsets.
3. Walk bar by bar through the eight 8th-note positions. Mark a KICK where the 35–120 Hz onset is ≥ 0.55 and ≥ 60 % of that bar's strongest. Mark a SNARE (accent) where the 1–4.5 kHz onset is ≥ 0.75 and at least 0.3 above the bar's median: at most two per bar, never on a kick.
4. Keep the strengths so quiet sections barely move the camera. Plot the kicks, snares and bar lines over the low-band envelope and check the pattern by eye before using it.
node · render loop (puppeteer + ffmpeg)
// render.mjs: node render.mjs shot.html 2.208 out.mp4   (needs puppeteer and ffmpeg)
import puppeteer from 'puppeteer';
import { spawn } from 'node:child_process';
import { pathToFileURL } from 'node:url';
import path from 'node:path';

const [page_, seconds, out] = process.argv.slice(2);
const FPS = 24, frames = Math.round(Number(seconds) * FPS);
const browser = await puppeteer.launch({ headless: true });
const page = await browser.newPage();
await page.setViewport({ width: 720, height: 1280, deviceScaleFactor: 1.5 });
await page.goto(pathToFileURL(path.resolve(page_)).href, { waitUntil: 'load' });
await page.evaluate(async () => { await document.fonts.ready; if (window.setup) await window.setup(); });

const ff = spawn('ffmpeg', ['-y', '-f', 'image2pipe', '-framerate', String(FPS), '-i', '-',
  '-frames:v', String(frames), '-c:v', 'libx264', '-crf', '16', '-pix_fmt', 'yuv420p', out], { stdio: ['pipe', 'inherit', 'inherit'] });
for (let i = 0; i < frames; i++) {
  await page.evaluate(t => window.renderFrame(t), i / FPS);
  ff.stdin.write(await page.screenshot({ type: 'png' }));
}
ff.stdin.end();
await new Promise(r => ff.on('close', r));
await browser.close();
